🔑 Chapter 41

Hashing

Why dict and set lookups are O(1) — the trick behind Python's fastest data structures.

🔑

🔑 Instant Lookup, No Searching

A list has to scan item by item to find something. A hash-based structure jumps straight to where the item should be — no searching required.

⚡ 1. The Problem With Searching Lists

students = ["Ravi", "Sita", "Amit", "Priya", "Karan"]   # a list
print("Amit" in students)   # has to check each item — O(n)
students = {"Ravi", "Sita", "Amit", "Priya", "Karan"}   # a set
print("Amit" in students)   # jumps straight there — O(1)

Same question, same data, wildly different speed at scale. A set and dict use hashing to achieve this.

🧮 2. What is a Hash Function?

A hash function takes any value and converts it into a number (a "hash"). That number decides exactly which "slot" in memory the value belongs to — so finding it later means computing the hash again and jumping straight there.

print(hash("Amit"))
print(hash("Ravi"))
print(hash(42))
-3798261444673148797 7183294756192834561 42
💡 The exact numbers vary by Python run — what matters is that the SAME input always produces the SAME hash within one run. That consistency is what lets Python find the value again instantly.

📚 Real-Life Analogy

A library that shelves books by a formula based on the title, instead of alphabetically searching every shelf. Given a title, you compute which shelf it's on directly — no browsing required.

🗺️ 3. How dict Uses Hashing

student_grades = {"Ravi": 78, "Sita": 92, "Amit": 65}

print(student_grades["Amit"])
65

Behind the scenes: Python computes hash("Amit"), uses that number to jump directly to the right internal slot, and reads the value there — no scanning through "Ravi" and "Sita" first. That's why dict lookups don't get slower as the dict grows.

⚠️ Only immutable types can be hashed — strings, numbers, tuples. Lists and dicts can't be dict keys or set members because they can change after being added, which would break their hash. 
bad_key = {[1, 2]: "value"}   # TypeError: unhashable type: 'list'
Traceback... TypeError: unhashable type: 'list'

💥 4. Hash Collisions

Two different values can sometimes produce the same hash (or the same slot after some math) — a collision. Python handles this automatically, but it's worth knowing it happens.

# Conceptually — not exact Python internals, but the idea:
# if hash("Amit") % table_size == hash("Karan") % table_size:
#     both compete for the same slot
#     Python stores both and checks equality when looking one up
ℹ️ You never write collision-handling code yourself — dict and set handle it internally. The only practical impact: a badly-designed custom __hash__ (rare, advanced) with too many collisions can slow lookups toward O(n).

🚀 5. Real Example — Speeding Up "Find Duplicates"

This mirrors the O(n²) → O(n) fix from Big-O, using hashing to skip repeated scanning.

# Slow — O(n²): for every item, scan the whole list again
def has_duplicate_slow(items):
    for i in range(len(items)):
        for j in range(len(items)):
            if i != j and items[i] == items[j]:
                return True
    return False

# Fast — O(n): a set gives O(1) "have I seen this before?" checks
def has_duplicate_fast(items):
    seen = set()
    for item in items:
        if item in seen:      # O(1) thanks to hashing
            return True
        seen.add(item)
    return False

numbers = list(range(100000)) + [500]   # one duplicate at the end
print(has_duplicate_fast(numbers))      # runs instantly
True

🚀 Challenge: Write count_unique_words(text) that returns how many DISTINCT words are in a string, using a set. 
def count_unique_words(text):
    words = text.lower().split()
    unique = set(words)      # hashing removes duplicates automatically
    return len(unique)

print(count_unique_words("the cat sat on the mat the cat ran"))   # 5

✍️ Chapter Summary

  • Hash function — converts a value into a number that decides its storage slot
  • dict/set lookups are O(1) because of this direct jump — no scanning
  • Only immutable types (str, int, tuple) can be hashed / used as dict keys
  • Swapping a list-scan for a set membership check is a common O(n²) → O(n) fix
