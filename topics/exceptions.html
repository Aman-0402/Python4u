Exception Handling & Debugging

Programs crash. Users lie. Files vanish. Handle it gracefully or look like Tom after the anvil.

💣

💣 When Things Go Wrong

Every program will crash eventually. The question is: does it crash with a helpful message, or does it explode like one of Wile E. Coyote's ACME gadgets?

⚡ 1. What is an Exception?

Exception = runtime error. Code is valid Python. It just blew up while running, usually due to bad data or missing resources.

🐱 Tom's Division Problem

Tom chases Jerry at speed ÷ distance. If distance = 0 (Jerry teleports), Python screams ZeroDivisionError. Tom's program crashes. Jerry laughs. Classic.

🛡️ 2. try / except — Catching the Crash

try:
Run code that might crash
except:
Run this if it crashes
else:
Run this ONLY if no crash
finally:
Run this ALWAYS (cleanup)

🐱 Homer's Donut Division

try:
    donuts = 12
    people = 0
    each = donuts / people
    print(f"Each person gets {each} donuts")
except ZeroDivisionError:
    print("Marge: Nobody home. All donuts are Homer's anyway.")
except ValueError as e:
    print(f"Input error: {e}")
Marge: Nobody home. All donuts are Homer's anyway.

🔎 Catching exception detail with as e

try:
    age = int("two cats and a banana")
except ValueError as e:
    print(f"Scooby Doo tried to enter his age: {e}")
Scooby Doo tried to enter his age: invalid literal for int() with base 10: 'two cats and a banana'

🔄 3. Multiple except Blocks

One try, many except. Each handles a different failure. Like SpongeBob's Krusty Krab order desk — different complaints, different responses.

def krusty_krab_order(item, quantity):
    try:
        menu = {"Krabby Patty": 3.99, "Kelp Shake": 1.99}
        price = menu[item]                    # KeyError if item not in menu
        total = price * int(quantity)         # ValueError if quantity not a number
        result = total / 0                    # pretend tax calc crashes
        return f"Total: ${total:.2f}"
    except KeyError:
        return f"Sorry, '{item}' not on menu. Try a Krabby Patty."
    except ValueError:
        return f"Quantity must be a number. '{quantity}' is not food math."
    except ZeroDivisionError:
        return "Tax system broken. Blame Squidward."

print(krusty_krab_order("Pizza", 2))
print(krusty_krab_order("Krabby Patty", "lots"))
print(krusty_krab_order("Krabby Patty", 2))
Sorry, 'Pizza' not on menu. Try a Krabby Patty. Quantity must be a number. 'lots' is not food math. Tax system broken. Blame Squidward.
💡 Use specific exceptions first, then broad ones. except Exception catches everything — useful as last resort, bad as first resort. Like catching all animals with one net.

✅ 4. else & finally

📁 Mr. Bean's File Reader

try:
    with open("shopping_list.txt", "r") as f:
        items = f.read()
except FileNotFoundError:
    print("Mr. Bean: lost the list again. Classic.")
else:
    print("List found!")
    print(items)        # only runs if NO exception
finally:
    print("Mr. Bean wanders off regardless.")    # ALWAYS runs
Mr. Bean: lost the list again. Classic. Mr. Bean wanders off regardless.
BlockWhen it runsUse for
tryAlways (attempts this first)Risky code
exceptOnly on matching errorHandle crash
elseOnly if NO exceptionSuccess path
finallyAlways, no matter whatCleanup (close files, etc.)

💥 5. raise — Throw Your Own Exceptions

Use raise to trigger exceptions yourself when inputs violate rules. Wile E. Coyote manually throws an ACME bomb — same idea, slightly less destructive.

def set_speed(speed):
    if speed < 0:
        raise ValueError("Speed can't be negative. Wile E. Coyote moves FORWARD.")
    if speed > 1000:
        raise ValueError("That's Road Runner speed. Not physically possible.")
    return f"Speed set to {speed} mph"

try:
    print(set_speed(500))
    print(set_speed(-10))
except ValueError as e:
    print(f"Speed Error: {e}")
Speed set to 500 mph Speed Error: Speed can't be negative. Wile E. Coyote moves FORWARD.

🪨 Custom Exception Classes

Inherit from Exception to create meaningful, domain-specific errors.

class CartoonLogicError(Exception):
    """When cartoon physics violate real physics."""
    pass

class InsufficientACMEBudget(Exception):
    """Wile E. can't afford the gadget."""
    def __init__(self, item, cost, budget):
        super().__init__(f"Can't buy '{item}' (costs ${cost}, budget ${budget})")
        self.item = item

def buy_acme(item, cost, budget):
    if cost > budget:
        raise InsufficientACMEBudget(item, cost, budget)
    return f"Purchased: {item}"

try:
    print(buy_acme("Giant Magnet", 500, 50))
except InsufficientACMEBudget as e:
    print(f"ACME Store: {e}")
ACME Store: Can't buy 'Giant Magnet' (costs $500, budget $50)

🔎 6. Debugging — Finding the Bug

Exception handling prevents crashes. Debugging finds WHY something's wrong. Different skills, both necessary.

💬

print() Debug

Oldest trick. Works everywhere. No setup needed. Indiana Jones level — crude but effective.

🔧

assert

Verify assumptions mid-code. Raises AssertionError if condition false. Good for sanity checks.

💻

VS Code Debugger

Breakpoints, step-through, watch variables. The professional way. Set up once, save hours.

💬 print() Debugging — Quick & Dirty

def calculate_tip(bill, percent):
    print(f"DEBUG: bill={bill}, type={type(bill)}")    # inspect inputs
    print(f"DEBUG: percent={percent}")
    tip = bill * (percent / 100)
    print(f"DEBUG: tip calculated = {tip}")
    return tip

total = calculate_tip("50", 15)    # bug: bill is string!
print(f"Tip: ${total}")
DEBUG: bill=50, type=<class 'str'> DEBUG: percent=15 Traceback... TypeError: can't multiply sequence by non-int of type 'float'

Print revealed the bug — bill is a string, not a number. Fix: bill = float(bill).

⛔ assert — Indiana Jones Floor Check

# Indiana Jones checks the floor BEFORE stepping
def calculate_discount(price, discount_pct):
    assert isinstance(price, (int, float)), f"Price must be number, got {type(price)}"
    assert 0 <= discount_pct <= 100, "Discount must be between 0 and 100"

    return price - (price * discount_pct / 100)

print(calculate_discount(100, 25))     # 75.0
print(calculate_discount(100, 150))    # AssertionError: Discount must be between 0 and 100
75.0 AssertionError: Discount must be between 0 and 100
⚠️ assert statements are disabled when Python runs with -O (optimise) flag. Use them for dev/testing, not production input validation.

Write safe_divide(a, b). Handle ZeroDivisionError and TypeError. Return the result or a funny error message. 
def safe_divide(a, b):
    try:
        return a / b
    except ZeroDivisionError:
        return "Can't divide by zero. Even ACME doesn't sell division by nothing."
    except TypeError:
        return f"Both must be numbers. Got {type(a).__name__} and {type(b).__name__}."

print(safe_divide(10, 2))       # 5.0

🚀 Challenge 2: Scooby Snack Validator
Write request_snacks(name, count). Raise ValueError if count < 1 or count > 10. Raise custom UnauthorizedSnackError if name is "Scrappy-Doo" (nobody likes Scrappy). 
class UnauthorizedSnackError(Exception):
    pass

def request_snacks(name, count):
    if name == "Scrappy-Doo":
        raise UnauthorizedSnackError("No snacks for Scrappy. Gang voted.")
    if not 1 <= count <= 10:
        raise ValueError(f"Count must be 1-10, not {count}.")
    return f"{name} gets {count} Scooby Snack(s)! Scooby-Dooby-Doo!"

for name, n in [("Shaggy", 5), ("Scrappy-Doo", 3), ("Scooby", 99)]:
    try:
        print(request_snacks(name, n))
    except UnauthorizedSnackError as e:
        print(f"Denied: {e}")
    except ValueError as e:
        print(f"Invalid count: {e}")
🚀 Challenge 3: Homer's Donut Shop
Ask user for item name and quantity. Catch ValueError (non-numeric quantity) + KeyError (item not in menu). Use else to print total, finally to print "Thanks for visiting!" 
menu = {
    "donut":    1.50,
    "burger":   4.99,
    "hotdog":   2.50,
    "duff beer": 3.00,
}

item = input("What do you want? ").lower()
qty  = input("How many? ")

try:
    price = menu[item]         # KeyError if not found
    count = int(qty)           # ValueError if not a number
    total = price * count
except KeyError:
    print(f"'{item}' not on the menu. Try: {list(menu.keys())}")
except ValueError:
    print(f"'{qty}' is not a valid number. Homer is confused.")
else:
    print(f"Total: ${total:.2f}. Mmmmm... {item}.")
finally:
    print("Thanks for visiting Homer's Donut Shop!")
