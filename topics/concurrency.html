Concurrency — Threading, Multiprocessing & asyncio

Do multiple things "at the same time" — waiting on network calls, crunching numbers, or handling many tasks at once.

⚡

⚡ Three Ways to Do Things Concurrently

Not every "run multiple things at once" problem needs the same tool. Python gives you three, each suited to a different kind of work.

🧵 1. Threading — Good for Waiting (I/O)

Use threading when your program spends time waiting — for a file, a network response, a database. Threads share memory and let one thread run while another waits.

import threading
import time

def download_file(name):
    print(f"Starting download: {name}")
    time.sleep(2)   # pretend this is a slow network call
    print(f"Finished: {name}")

t1 = threading.Thread(target=download_file, args=("report.pdf",))
t2 = threading.Thread(target=download_file, args=("data.csv",))

t1.start()
t2.start()
t1.join()
t2.join()
print("All downloads done")
Starting download: report.pdf Starting download: data.csv Finished: report.pdf Finished: data.csv All downloads done

Both downloads take ~2 seconds total (not 4), because they wait at the same time instead of one after another.

⚠️ 2. Race Conditions — When Threads Fight Over the Same Data

Threads share the same memory. If two threads read and update the same variable at the same time, updates can get lost — this is a race condition.

import threading

balance = 0

def deposit():
    global balance
    for _ in range(100000):
        balance += 1   # NOT atomic: read balance, add 1, write balance back

t1 = threading.Thread(target=deposit)
t2 = threading.Thread(target=deposit)

t1.start()
t2.start()
t1.join()
t2.join()

print(balance)   # expected 200000 — often prints something LESS
187342

balance += 1 looks like one step, but it's really three: read the value, add 1, write it back. If both threads read the same old value before either writes, one update gets overwritten — some deposits silently vanish.

🔒 Fixing it with a Lock

import threading

balance = 0
lock = threading.Lock()

def deposit():
    global balance
    for _ in range(100000):
        with lock:          # only one thread can be inside at a time
            balance += 1

t1 = threading.Thread(target=deposit)
t2 = threading.Thread(target=deposit)

t1.start()
t2.start()
t1.join()
t2.join()

print(balance)   # always 200000
200000
⚠️ A Lock forces threads to take turns around the risky code — one thread finishes its read-modify-write before another is allowed to start. This fixes correctness but reduces parallelism for that section, so lock only the smallest piece of code that actually needs protecting.

🖥️ 3. Multiprocessing — Good for Heavy CPU Work

Python threads can't run Python code on multiple CPU cores at once — because of something called the GIL (Global Interpreter Lock).

🔑 What is the GIL?

The GIL is a single lock built into the standard Python interpreter (CPython) that only lets one thread run Python bytecode at a time, even on a multi-core CPU. It exists to keep Python's internal memory management simple and safe.

That's why threading in section 1 helped — the threads were mostly waiting (for the network), not competing to run Python code at the same instant. But for CPU-bound work — actual number crunching — the GIL means threads take turns on one core instead of truly running in parallel.

For CPU-heavy work — big calculations, image processing — use separate processes instead.

from multiprocessing import Process

def calculate_squares(numbers):
    result = [n * n for n in numbers]
    print(f"Squares of {numbers}: {result}")

if __name__ == "__main__":
    p1 = Process(target=calculate_squares, args=([1, 2, 3],))
    p2 = Process(target=calculate_squares, args=([4, 5, 6],))

    p1.start()
    p2.start()
    p1.join()
    p2.join()
Squares of [1, 2, 3]: [1, 4, 9] Squares of [4, 5, 6]: [16, 25, 36]
⚠️ Each process has its own memory — no automatic variable sharing like threads. Use multiprocessing.Queue to pass data between processes.

🌀 4. asyncio — Good for Many I/O Tasks at Once

asyncio runs many waiting tasks on a single thread, switching between them while each one waits. Great for handling hundreds of network requests.

import asyncio

async def fetch_data(name, delay):
    print(f"Fetching {name}...")
    await asyncio.sleep(delay)   # non-blocking wait
    print(f"Got {name}")
    return name

async def main():
    results = await asyncio.gather(
        fetch_data("users", 2),
        fetch_data("orders", 1),
        fetch_data("products", 3),
    )
    print("All done:", results)

asyncio.run(main())
Fetching users... Fetching orders... Fetching products... Got orders Got users Got products All done: ['users', 'orders', 'products']

All three fetches happen concurrently — total time is ~3 seconds (the slowest one), not 6.

🧑‍💻 Practice

🚀 Challenge: Write an asyncio program that fetches "weather" and "news" concurrently, each taking 1 second, and prints both results. 
import asyncio

async def fetch(name):
    await asyncio.sleep(1)
    return f"{name} data ready"

async def main():
    weather, news = await asyncio.gather(fetch("weather"), fetch("news"))
    print(weather)
    print(news)

asyncio.run(main())

✍️ Chapter Summary

  • Threading — best for waiting on I/O (network, files)
  • Multiprocessing — best for heavy CPU calculations, uses multiple cores
  • asyncio — best for many concurrent I/O tasks on one thread
  • await pauses an async task without blocking the whole program
