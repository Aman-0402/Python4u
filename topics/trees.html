Trees — Binary Tree & BST

A branching structure — one root, each node with children — perfect for hierarchical data and fast lookups.

🌳

🌳 Data That Branches

File systems, org charts, HTML — real-world data is often hierarchical, not a flat line. A tree models "one parent, many children" naturally.

⚡ 1. Tree Vocabulary

TermMeaning
RootThe top node — has no parent
NodeAny single element in the tree
ChildA node directly connected below another node
LeafA node with no children
Binary TreeEach node has AT MOST 2 children ("left" and "right")

🗂️ Real-Life Analogy

A company org chart: the CEO is the root, managers are children of the CEO, employees are children of managers. Anyone with no one reporting to them is a leaf.

🔍 3. Binary Search Tree (BST) — Ordering Rule

A BST adds one rule: for every node, everything in its left subtree is smaller, everything in its right subtree is bigger. This makes searching fast.

class TreeNode:
    def __init__(self, value):
        self.value = value
        self.left = None
        self.right = None

class BST:
    def __init__(self):
        self.root = None

    def insert(self, value):
        if self.root is None:
            self.root = TreeNode(value)
        else:
            self._insert(self.root, value)

    def _insert(self, node, value):
        if value < node.value:
            if node.left is None:
                node.left = TreeNode(value)
            else:
                self._insert(node.left, value)
        else:
            if node.right is None:
                node.right = TreeNode(value)
            else:
                self._insert(node.right, value)

bst = BST()
for num in [10, 5, 15, 3, 7, 20]:
    bst.insert(num)

Each insert compares the new value against the current node and recurses left or right — this is recursion in action, walking down the tree.

🎯 4. Searching a BST — O(log n)

    def search(self, value):
        return self._search(self.root, value)

    def _search(self, node, value):
        if node is None:
            return False
        if node.value == value:
            return True
        elif value < node.value:
            return self._search(node.left, value)    # only look left
        else:
            return self._search(node.right, value)   # only look right

bst = BST()
for num in [10, 5, 15, 3, 7, 20]:
    bst.insert(num)

print(bst.search(7))     # True
print(bst.search(100))   # False
True False

Just like binary search on a sorted list, each comparison eliminates half the remaining tree — O(log n) on a balanced tree, instead of checking every node.

🚶 5. Traversals — Visiting Every Node

Three common orders to walk through a tree, each recursive.

    def inorder(self, node, result=None):
        if result is None:
            result = []
        if node:
            self.inorder(node.left, result)
            result.append(node.value)
            self.inorder(node.right, result)
        return result

bst = BST()
for num in [10, 5, 15, 3, 7, 20]:
    bst.insert(num)

print(bst.inorder(bst.root))
[3, 5, 7, 10, 15, 20]
💡 In-order (left, node, right) on a BST always visits values in sorted order — a free side effect of the BST ordering rule. Pre-order (node, left, right) is used to copy a tree. Post-order (left, right, node) is used to safely delete a tree bottom-up.

    def find_min(self, node):
        current = node
        while current.left:      # smallest value is always the leftmost node
            current = current.left
        return current.value

✍️ Chapter Summary

  • Tree — root, nodes, children, leaves; binary tree — max 2 children per node
  • BST rule — left subtree smaller, right subtree bigger than the node
  • BST search/insert — O(log n) on a balanced tree, using the same halving idea as binary search
  • In-order traversal of a BST always yields sorted order
