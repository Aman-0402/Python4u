📦 Chapter 25

Virtual Environments & Packaging

Keep each project's dependencies isolated, and share your code with others correctly.

📦

📦 One Toolbox Per Project

Without isolation, every project shares the same global set of installed packages — install a new version for one project and you might break another. A virtual environment gives each project its own private toolbox.

⚡ 1. Creating a Virtual Environment

# Create a virtual environment named "venv"
python -m venv venv

# Activate it
# Windows:
venv\Scripts\activate

# macOS / Linux:
source venv/bin/activate

Once activated, your terminal prompt usually shows (venv) — any pip install now only affects this project, not your whole system.

💡 Deactivate anytime with the command deactivate. It just turns off the isolation — nothing is deleted.

📥 2. Installing Packages

# Inside the activated venv
pip install requests
pip install pandas==2.1.0   # specific version

pip list                    # see installed packages
pip show requests           # details about one package

📄 3. requirements.txt — Sharing Your Setup

Save the exact packages your project needs so anyone else can install the same versions.

# Save current packages to a file
pip freeze > requirements.txt
# requirements.txt
requests==2.31.0
pandas==2.1.0
flask==3.0.0
# Someone else installs everything at once
pip install -r requirements.txt
ℹ️ Always commit requirements.txt to your repo, but never commit the venv/ folder itself — add it to .gitignore.

🧭 4. Modern Way — pyproject.toml

Newer projects describe dependencies and metadata in one standard file instead of requirements.txt.

# pyproject.toml
[project]
name = "student-tracker"
version = "1.0.0"
description = "Track student attendance and grades"
dependencies = [
    "requests>=2.31.0",
    "pandas>=2.1.0",
]

[build-system]
requires = ["setuptools>=68.0"]
build-backend = "setuptools.build_meta"

Tools like pip, poetry, and uv can all read this same file to install dependencies and build your package.

🗂️ 5. Typical Project Layout

student_tracker/
├── venv/                 # virtual environment (not committed)
├── student_tracker/      # your actual package code
│   ├── __init__.py
│   └── main.py
├── tests/
│   └── test_main.py
├── requirements.txt
├── pyproject.toml
└── README.md

✍️ Chapter Summary

  • python -m venv venv — create an isolated environment
  • venv\Scripts\activate / source venv/bin/activate — turn it on
  • pip freeze > requirements.txt — record dependencies
  • pip install -r requirements.txt — install everything on another machine
  • pyproject.toml — modern standard for project metadata + dependencies
