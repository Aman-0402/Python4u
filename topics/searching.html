Searching Algorithms

Two ways to find an item in a list — one that checks everything, one that's much smarter.

🔎

🔎 Finding a Needle in a List

in and .index() already search for you — but understanding how searching actually works explains why some lookups are instant and others crawl.

➡️ 1. Linear Search — Check Everything

Start at the first item, check each one in order, stop when found (or the list runs out). Works on ANY list — sorted or not.

def linear_search(items, target):
    for index, value in enumerate(items):
        if value == target:
            return index          # found it — return position
    return -1                     # not found

names = ["Ravi", "Sita", "Amit", "Priya"]
print(linear_search(names, "Amit"))    # 2
print(linear_search(names, "Karan"))   # -1
2 -1

Worst case: the target is last, or missing entirely — every item gets checked. That's O(n).

🪓 2. Binary Search — Divide and Conquer

Requires a sorted list. Check the middle item: if the target is smaller, ignore the entire right half; if bigger, ignore the entire left half. Repeat.

def binary_search(sorted_items, target):
    low, high = 0, len(sorted_items) - 1

    while low <= high:
        mid = (low + high) // 2
        if sorted_items[mid] == target:
            return mid
        elif sorted_items[mid] < target:
            low = mid + 1          # target is in the right half
        else:
            high = mid - 1         # target is in the left half

    return -1

numbers = [2, 5, 8, 12, 16, 23, 38, 45, 56, 72, 91]
print(binary_search(numbers, 23))   # 5
print(binary_search(numbers, 100))  # -1
5 -1

💡 Each step throws away half the remaining data — that's why binary search is O(log n). Searching 1,000,000 sorted items takes at most ~20 comparisons, not 1,000,000.

⚖️ 3. Linear vs Binary — When to Use Which

Linear SearchBinary Search
Requires sorted data?NoYes
Time complexityO(n)O(log n)
Works onAny listSorted lists/arrays only
Best forSmall or unsorted data, one-off searchLarge sorted data, repeated searches
⚠️ If your data isn't sorted and you only need to search it once, sorting first just to binary search is usually more expensive overall than a single linear search. Binary search wins when the data is already sorted, or you'll search it many times.

🚀 Challenge: Write binary_search_recursive(sorted_items, target, low, high) — same logic as above, but using recursion instead of a while loop. 
def binary_search_recursive(sorted_items, target, low, high):
    if low > high:
        return -1                       # base case: not found

    mid = (low + high) // 2
    if sorted_items[mid] == target:
        return mid                      # base case: found
    elif sorted_items[mid] < target:
        return binary_search_recursive(sorted_items, target, mid + 1, high)
    else:
        return binary_search_recursive(sorted_items, target, low, mid - 1)

numbers = [2, 5, 8, 12, 16, 23, 38, 45]
print(binary_search_recursive(numbers, 38, 0, len(numbers) - 1))   # 6

✍️ Chapter Summary

  • Linear search — checks every item in order, O(n), works on any list
  • Binary search — repeatedly halves the search space, O(log n), needs sorted data
  • Binary search wins on large, sorted, or repeatedly-searched data
