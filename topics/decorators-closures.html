Decorators & Closures

Wrap a function with extra behaviour — logging, timing, access checks — without changing its code.

🎁 Functions Wrapping Functions

In Python, functions are just values. You can pass them around, return them, and wrap one function inside another. That's the whole trick behind decorators.

🔒 1. Closures — A Function That Remembers

A closure is an inner function that remembers variables from its enclosing function, even after that function has finished running.

def make_multiplier(factor):
    def multiply(number):
        return number * factor   # remembers "factor"
    return multiply

double = make_multiplier(2)
triple = make_multiplier(3)

print(double(5))   # 10
print(triple(5))   # 15
10 15

multiply keeps a private copy of factor from when it was created. double and triple are separate functions with separate memories.

🎁 2. Decorators — Wrapping a Function

A decorator is a function that takes another function, adds behaviour around it, and returns the wrapped version.

Step by step, without @

def log_call(func):
    def wrapper(*args, **kwargs):
        print(f"Calling {func.__name__}")
        result = func(*args, **kwargs)
        print(f"{func.__name__} finished")
        return result
    return wrapper

def add(a, b):
    return a + b

add = log_call(add)   # manually wrap
print(add(2, 3))
Calling add add finished 5

Same thing with @ syntax

def log_call(func):
    def wrapper(*args, **kwargs):
        print(f"Calling {func.__name__}")
        result = func(*args, **kwargs)
        print(f"{func.__name__} finished")
        return result
    return wrapper

@log_call
def add(a, b):
    return a + b

print(add(2, 3))
Calling add add finished 5
💡 @log_call above def add(...) is just shorthand for add = log_call(add).

🎭 3. The Hidden Gotcha — functools.wraps

After decorating, add is now literally the wrapper function, not the original. That breaks introspection — anything checking the function's name or docstring gets the wrong answer.

The problem

def log_call(func):
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

@log_call
def add(a, b):
    """Add two numbers together."""
    return a + b

print(add.__name__)   # expected "add"
print(add.__doc__)    # expected "Add two numbers together."
wrapper None

The function's identity got silently swapped for the wrapper's — confusing for debugging, documentation tools, and anything using func.__name__.

The fix

from functools import wraps

def log_call(func):
    @wraps(func)              # copies __name__, __doc__, etc. from func onto wrapper
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

@log_call
def add(a, b):
    """Add two numbers together."""
    return a + b

print(add.__name__)   # add
print(add.__doc__)    # Add two numbers together.
add Add two numbers together.
⚠️ Always add @wraps(func) to a decorator's inner wrapper. It costs one line and prevents a real, commonly-hit bug in any code that introspects functions (debuggers, API doc generators, some testing frameworks).

🥞 4. Stacking Multiple Decorators

You can apply more than one decorator to the same function — they wrap from the bottom up, closest to the function first.

from functools import wraps

def bold(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        return f"<b>{func(*args, **kwargs)}</b>"
    return wrapper

def italic(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        return f"<i>{func(*args, **kwargs)}</i>"
    return wrapper

@bold
@italic
def greet(name):
    return f"Hello, {name}"

print(greet("Ravi"))
<b><i>Hello, Ravi</i></b>

Order matters: italic runs first (closest to the function), wrapping the result in <i>. Then bold wraps that entire result in <b>. Reading bottom-to-top tells you the actual execution order.

⏱️ 5. Practical Example — Timing a Function

import time

def timer(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        end = time.time()
        print(f"{func.__name__} took {end - start:.4f} seconds")
        return result
    return wrapper

@timer
def process_orders(count):
    total = sum(range(count))
    return total

process_orders(1000000)
process_orders took 0.0123 seconds

🔑 6. Decorator With Arguments

Add a third layer if the decorator itself needs settings.

def require_role(role):
    def decorator(func):
        def wrapper(user_role, *args, **kwargs):
            if user_role != role:
                return f"Access denied. Needs role: {role}"
            return func(user_role, *args, **kwargs)
        return wrapper
    return decorator

@require_role("admin")
def delete_user(user_role, username):
    return f"{username} deleted"

print(delete_user("admin", "test_account"))
print(delete_user("student", "test_account"))
test_account deleted Access denied. Needs role: admin

🚀 Challenge: Write a decorator uppercase_result that converts a function's string return value to uppercase. 
def uppercase_result(func):
    def wrapper(*args, **kwargs):
        result = func(*args, **kwargs)
        return result.upper()
    return wrapper

@uppercase_result
def greet(name):
    return f"hello, {name}"

print(greet("ravi"))   # HELLO, RAVI

✍️ Chapter Summary

  • Closure — inner function that remembers outer function's variables
  • Decorator — a function that wraps another function to add behaviour
  • @decorator is shorthand for func = decorator(func)
  • Use *args, **kwargs in the wrapper to support any function signature
