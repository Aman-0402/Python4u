🌀 Chapter 35

Recursion

A function that calls itself to break a big problem into smaller identical ones.

🌀

🌀 Solve the Small Case, Trust the Rest

Recursion means a function calls itself with a smaller version of the same problem, until it hits a case simple enough to answer directly.

⚡ 1. The Two Required Parts

Every recursive function needs exactly two things, or it never stops.

PartJob
Base caseThe simplest input — answered directly, no further recursion
Recursive caseCalls itself with a smaller/simpler input, moving toward the base case
 
def countdown(n):
    if n <= 0:              # base case — stops the recursion
        print("Liftoff!")
        return
    print(n)
    countdown(n - 1)        # recursive case — smaller problem

countdown(3)
3 2 1 Liftoff!
⚠️ Forget the base case, or never actually move toward it, and you get infinite recursion — Python stops you with RecursionError: maximum recursion depth exceeded.

🔢 2. Classic Example — Factorial

factorial(5) = 5 × 4 × 3 × 2 × 1. Notice: factorial(5) = 5 × factorial(4) — the problem contains a smaller version of itself.

def factorial(n):
    if n == 0 or n == 1:        # base case
        return 1
    return n * factorial(n - 1)  # recursive case

print(factorial(5))
120

📚 3. Tracing the Call Stack

Each recursive call pauses and waits for the one below it to finish — Python keeps track of all the paused calls on the call stack.

factorial(4)
= 4 * factorial(3)
      = 4 * (3 * factorial(2))
            = 4 * (3 * (2 * factorial(1)))
                  = 4 * (3 * (2 * 1))            <- base case hit, unwinding begins
            = 4 * (3 * 2)
      = 4 * 6
= 24

Calls go "down" (4 → 3 → 2 → 1) until the base case, then results multiply back "up" as each paused call resumes with the answer it was waiting for.

💡 Python's default recursion limit is 1000 calls deep (sys.getrecursionlimit()). Very deep recursion (like processing 100,000 items one-by-one) will crash — a loop is usually the safer choice for that.

🍯 4. Fibonacci — Multiple Recursive Calls

Each Fibonacci number is the sum of the two before it: 0, 1, 1, 2, 3, 5, 8, 13...

def fibonacci(n):
    if n <= 1:                                # base case
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)  # two recursive calls

for i in range(8):
    print(fibonacci(i), end=" ")
0 1 1 2 3 5 8 13
⚠️ This version recalculates the same values many times — fibonacci(5) calls fibonacci(3) twice, fibonacci(2) three times, and so on. It's O(2ⁿ) — extremely slow for large n. Fixed below.

🧠 5. Speeding It Up — Memoization

Cache results you've already computed so repeated sub-problems are answered instantly instead of recalculated.

def fibonacci_fast(n, cache={}):
    if n in cache:
        return cache[n]
    if n <= 1:
        return n
    result = fibonacci_fast(n - 1, cache) + fibonacci_fast(n - 2, cache)
    cache[n] = result
    return result

print(fibonacci_fast(50))   # instant, vs. plain recursion which would take ages
12586269025

This turns O(2ⁿ) into O(n) — each Fibonacci number gets computed exactly once, ever.

📁 6. Real Use — Exploring Nested Folders

Recursion shines whenever data contains smaller versions of itself — folders containing folders, for example.

import os

def list_files(folder, depth=0):
    for item in os.listdir(folder):
        path = os.path.join(folder, item)
        print("  " * depth + item)
        if os.path.isdir(path):
            list_files(path, depth + 1)   # recurse into the subfolder

list_files("my_project")
main.py utils helpers.py config.py tests test_main.py

🚀 Challenge: Write a recursive function sum_digits(n) that returns the sum of a number's digits (e.g. sum_digits(1234) → 10). 
def sum_digits(n):
    if n < 10:                  # base case — single digit
        return n
    return n % 10 + sum_digits(n // 10)   # last digit + rest of the number

print(sum_digits(1234))   # 1+2+3+4 = 10

✍️ Chapter Summary

  • Every recursive function needs a base case (stops it) and a recursive case (shrinks the problem)
  • Each call pauses on the call stack until the base case is hit, then results unwind back up
  • Naive recursion can repeat work — memoization (caching) fixes this
  • Good fit for self-similar data: folders, trees, nested lists
