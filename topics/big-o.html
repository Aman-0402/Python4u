📈 Chapter 34

Big-O / Time Complexity

A common language for describing how an algorithm's speed changes as input size grows.

📈

📈 How Slow Does It Get?

Two functions can both "work" but behave very differently with 10,000,000 items instead of 10. Big-O describes that growth pattern, not exact seconds.

⚡ 1. Why Not Just Time It?

Timing a function tells you about one machine, one moment. Big-O tells you how the work grows as input size (n) grows — true on any computer, forever.

def print_first(items):
    print(items[0])   # 1 step, no matter how big items is

def print_all(items):
    for item in items:
        print(item)    # n steps — grows with input size

print_first takes the same time whether the list has 5 items or 5 million. print_all takes longer as the list grows. Big-O captures exactly this difference.

📊 2. Common Big-O Classes — Fastest to Slowest

NotationNameMeaningExample
O(1)ConstantSame time regardless of input sizeitems[0]
O(log n)LogarithmicCuts the problem in half each stepBinary search
O(n)LinearTime grows directly with input sizeLoop through a list once
O(n log n)LinearithmicSlightly worse than linearMerge sort, quick sort (avg)
O(n²)QuadraticTime grows with the square of input sizeNested loop over the same list
💡 Big-O describes the worst case growth trend, ignoring constants. O(2n) and O(n) are both just written O(n) — Big-O cares about the shape of growth, not the exact multiplier.

🔍 3. O(1) — Constant Time

def get_first_student(students):
    return students[0]   # always exactly 1 step

students = ["Ravi", "Sita", "Amit"] * 1000
print(get_first_student(students))   # instant, regardless of list size
Ravi

➡️ 4. O(n) — Linear Time

def find_student(students, name):
    for student in students:      # worst case: check every single item
        if student == name:
            return True
    return False

students = ["Ravi", "Sita", "Amit"]
print(find_student(students, "Amit"))   # 3 steps worst case
print(find_student(["A"] * 1000000, "Z"))   # 1,000,000 steps worst case
True False

Double the list size, double the worst-case work — that's the signature of O(n).

🔀 5. O(n²) — Quadratic Time (Watch Out!)

def has_duplicate(items):
    for i in range(len(items)):
        for j in range(len(items)):
            if i != j and items[i] == items[j]:
                return True
    return False

print(has_duplicate([1, 2, 3, 4]))          # false, but checked 16 pairs
print(has_duplicate([1, 2, 3, 3]))          # true
False True

A nested loop over the same data means for every item, you scan every OTHER item — n * n total steps. 10 items = 100 checks. 1,000 items = 1,000,000 checks. This is the classic beginner performance trap.

⚠️ The same "find duplicates" problem can be solved in O(n) using a set to track seen items instead of a nested loop — see the practice challenge below.

🪓 6. O(log n) — Logarithmic Time

Binary search cuts the search space in half every step, instead of checking one item at a time.

def binary_search(sorted_list, target):
    low, high = 0, len(sorted_list) - 1
    steps = 0
    while low <= high:
        steps += 1
        mid = (low + high) // 2
        if sorted_list[mid] == target:
            print(f"Found in {steps} steps")
            return mid
        elif sorted_list[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return -1

numbers = list(range(1, 1000001))   # 1 million sorted numbers
binary_search(numbers, 999999)
Found in 20 steps

Finding one item among 1,000,000 took only 20 comparisons — because each step eliminates half the remaining data. See Searching for the full walkthrough.

🧑‍💻 Practice

🚀 Challenge: Rewrite has_duplicate from section 5 to run in O(n) instead of O(n²), using a set. 
def has_duplicate(items):
    seen = set()
    for item in items:          # single pass — O(n)
        if item in seen:        # set lookup is O(1)
            return True
        seen.add(item)
    return False

print(has_duplicate([1, 2, 3, 3]))   # True, and much faster on large lists

✍️ Chapter Summary

  • Big-O describes growth trend, not exact timing
  • O(1) — constant, O(log n) — logarithmic, O(n) — linear, O(n log n), O(n²) — quadratic
  • Nested loops over the same data are a common O(n²) trap
  • set/dict lookups are O(1) — a frequent way to speed up O(n²) code to O(n)
