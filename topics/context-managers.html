Context Managers

The with statement — guaranteed setup and cleanup, even if something crashes in between.

🔐

🔐 Setup, Use, Cleanup — Automatically

Opening a file, a database connection, or a lock all follow the same pattern: open it, use it, close it. with guarantees the "close it" part always happens.

📁 1. The Problem Without with

f = open("notes.txt", "w")
f.write("Hello")
# if an error happens here, f.close() never runs!
f.close()
⚠️ If an exception happens between open() and close(), the file stays open — a resource leak.

Fixed with with

with open("notes.txt", "w") as f:
    f.write("Hello")
# file is automatically closed here, even if an error occurred

with calls f.close() for you automatically when the block ends — success or failure.

⚙️ 2. Building Your Own Context Manager (Class)

Any class with __enter__ and __exit__ methods can be used with with.

class Timer:
    def __enter__(self):
        import time
        self.start = time.time()
        print("Timer started")
        return self

    def __exit__(self, exc_type, exc_value, traceback):
        import time
        elapsed = time.time() - self.start
        print(f"Timer stopped: {elapsed:.4f}s")

with Timer():
    total = sum(range(1000000))
    print(f"Sum: {total}")
Timer started Sum: 499999500000 Timer stopped: 0.0512s
MethodRuns when
__enter__At the start of the with block (setup)
__exit__At the end, always — even after an error (cleanup)

✨ 3. Simpler Way — @contextmanager

Using a generator function with the contextlib decorator avoids writing a whole class.

from contextlib import contextmanager

@contextmanager
def db_connection(name):
    print(f"Opening connection to {name}")
    yield f"connection:{name}"     # this value goes to "as conn"
    print(f"Closing connection to {name}")

with db_connection("students_db") as conn:
    print(f"Using {conn}")
Opening connection to students_db Using connection:students_db Closing connection to students_db

Code before yield = setup. Code after yield = cleanup, and it still runs even if the block raises an error.

🔗 4. Multiple Context Managers

with open("input.txt") as infile, open("output.txt", "w") as outfile:
    for line in infile:
        outfile.write(line.upper())

Both files are opened, used, then both are closed automatically — even if writing fails halfway through.

@contextmanager
def announce(task):
