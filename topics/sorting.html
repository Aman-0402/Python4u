Sorting Algorithms

sorted() does it in one line — here's what's actually happening, and why some approaches are much faster than others.

🔀

🔀 Putting Things in Order

Sorting shows up everywhere — leaderboards, search results, scheduling. Simple sorts are easy to understand but slow at scale; smarter sorts trade a bit of complexity for real speed.

🫧 1. Bubble Sort — Simple but Slow

Repeatedly compare neighboring pairs and swap if they're in the wrong order. Large values "bubble" toward the end each pass.

def bubble_sort(items):
    n = len(items)
    for i in range(n):
        for j in range(0, n - i - 1):
            if items[j] > items[j + 1]:
                items[j], items[j + 1] = items[j + 1], items[j]   # swap
    return items

marks = [64, 25, 12, 22, 11]
print(bubble_sort(marks))
[11, 12, 22, 25, 64]

Nested loop over the same list — this is O(n²). Fine for small lists, painfully slow for large ones.

🎯 2. Selection Sort

Find the smallest remaining item, swap it to the front, then repeat for the rest of the list.

def selection_sort(items):
    n = len(items)
    for i in range(n):
        min_index = i
        for j in range(i + 1, n):
            if items[j] < items[min_index]:
                min_index = j
        items[i], items[min_index] = items[min_index], items[i]
    return items

marks = [64, 25, 12, 22, 11]
print(selection_sort(marks))
[11, 12, 22, 25, 64]

Also O(n²) — still a nested loop — but makes fewer actual swaps than bubble sort (one swap per outer pass instead of many).

✂️ 3. Merge Sort — Divide and Conquer

Split the list in half repeatedly until each piece has 1 item (already "sorted"), then merge the pieces back together in order.

def merge_sort(items):
    if len(items) <= 1:
        return items                    # base case: 1 item is already sorted

    mid = len(items) // 2
    left = merge_sort(items[:mid])      # recursively sort left half
    right = merge_sort(items[mid:])     # recursively sort right half

    return merge(left, right)

def merge(left, right):
    result = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1
    result.extend(left[i:])             # add any leftovers
    result.extend(right[j:])
    return result

marks = [64, 25, 12, 22, 11, 90, 5]
print(merge_sort(marks))
[5, 11, 12, 22, 25, 64, 90]

Splitting takes O(log n) levels, and merging at each level costs O(n) — together that's O(n log n), dramatically faster than O(n²) for large lists.

💡 This is a textbook use of recursion — the base case is a 1-item list, the recursive case splits the problem in half.

⚠️ In real projects, always use Python's built-in sorted() or list.sort() — it's a highly optimized O(n log n) algorithm (Timsort) written in C. Writing your own sort is for learning how sorting works, not for production code. 
marks = [64, 25, 12, 22, 11]
print(sorted(marks))                       # ascending
print(sorted(marks, reverse=True))         # descending
print(sorted(marks, key=lambda x: -x))     # custom rule
[11, 12, 22, 25, 64] [64, 25, 22, 12, 11] [64, 25, 22, 12, 11]

🚀 Challenge: Use sorted() with a key to sort a list of student dicts by their "marks" value, highest first. 
students = [
    {"name": "Ravi", "marks": 78},
    {"name": "Sita", "marks": 92},
    {"name": "Amit", "marks": 65},
]

ranked = sorted(students, key=lambda s: s["marks"], reverse=True)
for s in ranked:
    print(s["name"], s["marks"])
# Sita 92
# Ravi 78
# Amit 65

✍️ Chapter Summary

  • Bubble sort & selection sort — simple, O(n²), fine for small lists
  • Merge sort — splits & merges recursively, O(n log n), scales much better
  • Always use sorted() / .sort() in real code — highly optimized built-in
  • key= lets you sort by any custom rule, not just default ordering
